# Cryptocurrency Services Build Plan

## Package Slice

1. Replace the placeholder marker with an executable APG capability package.
2. Define the capability contract, configuration, rule engine, UI routes,
   theme, Bytewax lifecycle events, dependencies, and provider-neutral agent
   roles.
3. Implement dependency-light domain models and runtime normalization helpers.
4. Implement service methods for assets, custody accounts, balances, orders,
   trades, transfers, compliance screening, price snapshots, reviews, agents,
   batches, and dashboard summaries.
5. Add process-local API helpers, UI view models, publishable app entrypoint,
   semantic model, package manifest, release report, and focused tests.
6. Update fintech metadata, catalog README counts, and progress log.
7. Verify with compile checks, focused pytest, app self-test, APG inspect,
   publish-plan, implementation audit, lifecycle audit, global audits, hygiene
   scans, and `git diff --check`.

## Review Criteria

- Rule evaluation happens before state mutation.
- Configuration requirements are enforced by service methods.
- UI and theme metadata are complete enough for generated applications.
- Bytewax remains the only lifecycle stream processor.
- Agent support remains provider-neutral across Codex, Claude Code, OpenCode,
  and Pi.
- Live exchanges, custody APIs, order routing, signing, market data, and chain
  access remain adapter responsibilities.
