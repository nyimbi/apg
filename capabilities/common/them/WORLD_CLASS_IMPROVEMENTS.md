# THEM - World Class Improvements

### I1. Async-Native Service Layer
**Category**: Architecture | **Justification**: All I/O-bound operations (DB writes, asset uploads, preview rendering, NATS publishing) block the event loop when synchronous. Async-native service methods eliminate thread-pool overhead and allow 10-50x higher concurrency with no additional infrastructure. | **Implementation**: Convert all public service methods to `async def`; use `asyncio.gather` for fan-out operations (multi-viewport previews, multi-tenant rollouts); accept async adapters via dependency injection at construction time. | **Competitor**: Shopify Polaris token pipeline uses fully async Rails Action Cable; Figma's design-system API is async throughout.

### I2. NATS JetStream Lifecycle Events
**Category**: Streaming | **Justification**: Bytewax consumes events from NATS subjects. Publishing theme lifecycle events directly to NATS JetStream gives every downstream processor (compliance, analytics, rollout coordinators) real-time, durable, ordered delivery — without polling. Kafka requires a broker cluster; NATS embeds in 10 MB. | **Implementation**: Inject an async NATS client at construction; `publish_theme`, `update_tokens`, `add_brand_asset`, and `apply_tenant_theme` each `await nats_client.publish(subject, payload)` after writing state; subject schema: `apg.them.<event_type>.<tenant_id>`. | **Competitor**: Storybook token sync uses Kafka topics; APG uses NATS for sub-millisecond delivery without broker overhead.

### I3. Perceptual Dark-Mode via OKLCH Colour Space
**Category**: Colour Science | **Justification**: Naively inverting RGB produces colours with mismatched perceived lightness — a dark blue looks almost black while a dark red looks bright. OKLCH inversion preserves hue and chroma while only adjusting lightness, producing perceptually uniform dark palettes that pass WCAG contrast without manual correction. | **Implementation**: Parse hex → sRGB → linear sRGB → OKLAB → OKLCH; flip L to `1 - L`; convert back; emit hex. Expose `dark_mode_oklch` strategy alongside existing `invert`. | **Competitor**: Radix UI uses OKLCH for its automatic dark-mode palette; Material Design 3 colour system is OKLCH-based.

### I4. Live Token Diff and Rollback
**Category**: Governance | **Justification**: Token version numbers increment but there is no mechanism to see what changed between versions or to revert. A diffing layer lets designers audit changes precisely and roll back a single misbehaving token group without touching others — reducing MTTR from hours to seconds. | **Implementation**: `async token_diff(tenant_id, theme_id, from_version, to_version)` walks `ThemeTokenRecord` history and returns added/removed/changed keys; `async token_rollback(tenant_id, theme_id, group, target_version)` re-applies historical token values as a new version record. | **Competitor**: Salesforce Lightning Design System has token changelog API; Figma Tokens plugin has version diffing.

### I5. Multi-Surface Contrast Matrix
**Category**: Accessibility | **Justification**: Current audit checks each colour token against white only. Real UIs layer colours: text on card, card on page, icon on button. A contrast matrix checks every foreground/background pair defined in the token set, surfacing failures that single-token audits miss — critical for WCAG 2.1 AA/AAA certification. | **Implementation**: `async contrast_matrix(tenant_id, theme_id)` groups tokens into `foreground` and `background` buckets by naming convention; computes the full N×M ratio table; flags pairs below 4.5 (AA normal) and 3.0 (AA large); returns structured violation report with fix suggestions per pair. | **Competitor**: Adobe Spectrum performs full colour-pair analysis; Stark Figma plugin does the same.

### I6. Design Token Schema Validation via W3C DTCG Format
**Category**: Interoperability | **Justification**: The Design Token Community Group (W3C DTCG) format is the emerging standard adopted by Figma, Style Dictionary 4, and Tokens Studio. Validating exported tokens against DTCG schema ensures round-trip fidelity with design tools and eliminates silent type coercion bugs when tokens move between systems. | **Implementation**: `async validate_dtcg(tenant_id, theme_id)` exports tokens as DTCG JSON and validates against the published JSON Schema; returns a structured report of schema violations, unsupported types, and missing required fields. `export_design_tokens` gains a `dtcg` format option. | **Competitor**: Tokens Studio (Figma plugin) and Style Dictionary 4 both use DTCG as primary format.

### I7. Tenant Theme Inheritance Graph
**Category**: Composability | **Justification**: `theme_inherit` creates parent-child relationships but there is no way to traverse the graph, detect cycles, or compute the fully-resolved token set at any node. Applications that white-label multi-level hierarchies (platform → partner → end-customer) need graph-aware token resolution to avoid override conflicts and infinite loops. | **Implementation**: `async resolve_token_graph(tenant_id, theme_id)` walks `fallback_theme_id` pointers up to depth 10 (cycle guard), merges token layers bottom-up (child overrides parent), and returns the fully-resolved token map with provenance per key. `async theme_inheritance_graph(tenant_id)` returns adjacency list and depth metrics. | **Competitor**: Tailwind CSS token cascading; Vanilla Extract theme contract inheritance.

### I8. Real-Time Preview via NATS WebSocket Bridge
**Category**: Developer Experience | **Justification**: Designers currently trigger preview generation as a discrete async step. A NATS-to-WebSocket bridge lets the browser subscribe to `apg.them.preview.<tenant_id>` and receive updated preview artifacts within milliseconds of token changes — eliminating the refresh cycle that wastes 30-60 seconds per iteration. | **Implementation**: `async stream_preview_updates(tenant_id, theme_id, callback)` subscribes to the NATS subject and invokes `callback(preview_payload)` on each message. Flask-AppBuilder view adds a `/them/preview/stream` SSE endpoint backed by the same subject. | **Competitor**: Storybook Hot Module Replacement; Chromatic real-time visual diffing.

### I9. AI-Assisted Colour Palette Generation
**Category**: AI Augmentation | **Justification**: Designers often start from a single brand hex and need a full complementary palette. An LLM-augmented generator that understands colour theory, WCAG constraints, and brand personality produces palettes that pass accessibility gates on the first attempt — cutting palette iteration from days to minutes. | **Implementation**: `async generate_palette(tenant_id, seed_hex, palette_size, wcag_level, brand_keywords)` computes analogous/triadic/complementary candidates in OKLCH, filters by contrast requirements, and optionally calls a local Ollama model for brand-aligned naming and mood annotation. Returns scored candidates ready for `update_tokens`. | **Competitor**: Adobe Firefly Colour; Huemint.com; Coolors AI palette.

### I10. Semantic Token Aliases
**Category**: Design System | **Justification**: Hard-coding hex values in component overrides creates a maintenance nightmare when the base palette changes. Semantic aliases (`color.action.primary` → `{color.brand.blue.500}`) decouple component semantics from raw values — one base-token change propagates everywhere. This is the foundation of scalable design systems at Atlassian, IBM, and Salesforce. | **Implementation**: Token values starting with `{` and ending with `}` are treated as aliases. `async resolve_aliases(tenant_id, theme_id)` performs recursive resolution with cycle detection. `generate_css_variables` resolves aliases before emitting CSS variables. Add `alias_depth` and `unresolved_aliases` to export metadata. | **Competitor**: Style Dictionary alias resolution; Figma variable aliases; Primer Design Tokens.

### I11. Multi-Tenant Rollout Canary Strategy
**Category**: Deployment Safety | **Justification**: Publishing a theme to 1000 tenants in one batch with no staged rollout is high-risk. A canary strategy gates progressive rollout behind real-time signal evaluation: if error rates or contrast-violation rates spike in the first cohort, the rollout halts automatically before 95% of tenants are affected. | **Implementation**: `async canary_rollout(tenant_id, theme_id, target_tenant_ids, cohort_size, halt_on_violation_rate)` partitions `target_tenant_ids` into cohorts; applies theme to each cohort; after each cohort calls `theme_audit_accessibility` on sampled tenants; halts if violation rate exceeds threshold; publishes progress to `apg.them.rollout.<tenant_id>` NATS subject. | **Competitor**: LaunchDarkly progressive rollout; Unleash feature flags; Optimizely staged deployments.

### I12. Style Dictionary Integration and Build Pipeline
**Category**: Toolchain | **Justification**: Style Dictionary is the industry-standard token transformation tool used by IBM Carbon, Atlassian, and Adobe. Exporting THEM tokens directly to Style Dictionary format and providing a build-pipeline hook means tokens flow automatically into mobile (iOS/Android), web, and design-tool artefacts without manual copy-paste. | **Implementation**: `async build_style_dictionary(tenant_id, theme_id, platforms)` calls `export_design_tokens(format="style_dictionary")`; writes platform-specific transform configs; invokes Style Dictionary CLI via `asyncio.create_subprocess_exec`; returns build artefact paths per platform. Supported platforms: `css`, `scss`, `ios_swift`, `android_xml`, `js_es6`. | **Competitor**: IBM Carbon Token Pipeline; Salesforce Lightning Design System token build.

### I13. Theme Snapshot and Time-Travel Audit
**Category**: Compliance | **Justification**: Regulatory requirements (GDPR, SOC 2, WCAG audit trails) demand that organisations reconstruct the exact visual state of an application at any past point in time. Full theme snapshots stored immutably — rather than just token version numbers — enable forensic replay of "what did tenant X see on date Y". | **Implementation**: `async snapshot_theme(tenant_id, theme_id, label)` serialises all current tokens, assets, overrides, breakpoints, and accessibility audit results into a single immutable JSON blob stored under a snapshot ID; `async restore_theme_snapshot(tenant_id, snapshot_id)` re-applies the blob as a new version without mutating history. | **Competitor**: Figma version history; Chromatic visual baseline snapshots; Storybook Storyshots.

### I14. Figma Variables Two-Way Sync
**Category**: Design-Dev Handoff | **Justification**: The industry's biggest friction point is keeping Figma variables in sync with production tokens. A two-way sync adapter imports Figma variable collections via the Figma REST API and maps them to THEM token groups — and exports updated THEM tokens back to Figma — eliminating duplicate source-of-truth maintenance. | **Implementation**: `async import_figma_variables(tenant_id, theme_id, figma_file_key, figma_token, updated_by)` calls Figma REST API, maps variable collections to token groups, calls `update_tokens`; `async export_to_figma(tenant_id, theme_id, figma_file_key, figma_token)` builds Figma variable payload and PATCHes the file. Use `httpx.AsyncClient` for all calls. | **Competitor**: Tokens Studio Figma plugin sync; Specify design data platform; Supernova.io.

### I15. Governance Scorecard and SLA Reporting
**Category**: Observability | **Justification**: Heads of design and engineering need a single-pane view: which tenants are on approved themes, which have stale tokens, which have unresolved WCAG violations, and what the mean time to theme publication is. Without this, governance is anecdotal and SLA breaches go undetected until a compliance audit. | **Implementation**: `async governance_scorecard(tenant_id, period_days)` aggregates: theme freshness (days since last token update), accessibility compliance rate, publication approval lag (time from preview to publish), asset licensing coverage, and rollout success rate; returns a structured score per dimension (0–100) and an overall health grade (A–F). Persists scorecard history for trend analysis. | **Competitor**: Specify governance dashboard; Zeroheight design system health metrics; Supernova component adoption tracking.
