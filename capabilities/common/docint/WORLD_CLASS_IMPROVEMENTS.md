# Document Intelligence — World-Class Improvements

### I1. Multi-Modal Vision-Language Model OCR
**Category**: Core Pipeline | **Justification**: LLaVA / Qwen-VL zero-shot understanding of scanned handwriting, rotated pages, and low-contrast stamps cuts error rates 40-60% vs Tesseract on real-world African business documents — eliminates the separate OCR preprocessing step entirely. | **Implementation**: Replace `_simulate_ocr_text` with an `async def _run_vlm_ocr` that base64-encodes each page image and calls `ollama.chat(model="llava:13b", images=[...])`. Cache results by `content_hash`. | **Competitor**: Google Document AI Vision, AWS Textract (cloud-only).

### I2. Layout-Aware Table and Column Extraction
**Category**: Extraction Quality | **Justification**: Line-item tables in invoices and bank statements are structurally destroyed by pure-text OCR. TATR (Table Transformer) or LayoutLMv3 preserves row/column structure, enabling per-line reconciliation and multi-currency summation. | **Implementation**: Add `async def extract_table_regions(document_id, page_image_b64)` using a locally hosted LayoutLMv3 endpoint; store `table_cells` in extraction result alongside `extracted_fields`. | **Competitor**: Adobe Acrobat AI Tables, Rossum.ai.

### I3. Confidence-Weighted Human-in-the-Loop Escalation
**Category**: Quality Assurance | **Justification**: Fully automated pipelines silently corrupt low-confidence extractions. Routing fields with confidence < threshold to a review queue reduces downstream accounting errors by order-of-magnitude. | **Implementation**: Add `async def flag_for_review(document_id, field_names, reason)` and `async def resolve_review(review_id, corrections)`. Store review queue per tenant. Publish `docint.review_required` events to NATS. | **Competitor**: Hyperscience IDP, IBM Datacap.

### I4. NATS-Backed Async Document Processing Queue
**Category**: Scalability | **Justification**: Synchronous request-response for OCR+LLM chains blocks web workers for 5-30 seconds. NATS JetStream queue decouples submission from processing, enables horizontal worker scaling, and gives durable retry semantics. | **Implementation**: Add `async def enqueue_document(document_id, priority)` that publishes to `docint.process.{tenant_id}` subject; add `async def start_worker(nats_url, concurrency)` that pulls and executes pipelines. | **Competitor**: AWS SQS + Textract async, Azure Form Recognizer async API.

### I5. Document Deduplication and Change Detection
**Category**: Efficiency | **Justification**: AP departments re-upload identical invoices causing duplicate payments. SHA-256 + perceptual hash (pHash) deduplication with configurable similarity threshold blocks duplicates before billing is triggered. | **Implementation**: Extend `submit_document` to call `async def find_duplicate(content_hash, tenant_id)` that checks the hash store; return `{"status": "duplicate", "original_id": ...}` when match found. Add pHash comparison for near-duplicate image files. | **Competitor**: Rossum.ai duplicate detection, Billtrust.

### I6. Structured Confidence Scores Per Field
**Category**: Extraction Quality | **Justification**: A single document-level confidence score hides that `total_amount` might be 0.99 while `vendor_address` is 0.43. Per-field confidence enables targeted re-verification and downstream field-level SLA tracking. | **Implementation**: Return `extracted_fields` as `{"field_name": {"value": ..., "confidence": 0.97, "source": "ocr|llm", "bbox": [x,y,w,h]}}`. Update `ExtractionResult` model; add `async def get_low_confidence_fields(document_id, threshold)`. | **Competitor**: Mindee API, AWS Textract AnalyzeDocument.

### I7. Contract Clause Classification and Risk Scoring
**Category**: Contract Intelligence | **Justification**: Manually scanning contracts for liability caps, indemnity, IP assignment, and non-compete clauses takes 2-4 hours per document. Clause-level classification with a fine-tuned LLM cuts this to < 30 seconds. | **Implementation**: Add `async def classify_contract_clauses(document_id, model)` that segments contract text into paragraphs and calls an Ollama model with a clause taxonomy prompt; store `{"clause_type": "indemnity", "text": ..., "risk_score": 0.82}` per clause. | **Competitor**: LawGeex, Kira Systems, SpotDraft.

### I8. Multi-Language and Script Support
**Category**: Internationalization | **Justification**: East African business documents mix English, Swahili, Arabic (for Islamic finance), and sometimes Amharic. Single-language OCR/LLM misses critical fields in mixed-language documents. | **Implementation**: Add `async def detect_language(document_id)` using `langdetect` on OCR output; route to appropriate Ollama model variant (`aya:8b` for multilingual). Store `detected_language` and `script_type` in document record. | **Competitor**: Google Cloud Translation + Document AI, Abbyy FineReader multilingual.

### I9. KYC/AML Watchlist Cross-Referencing
**Category**: Compliance | **Justification**: Verifying an ID document is necessary but not sufficient for KYC — extracted names must be screened against OFAC, UN sanctions, and local CRB/CBK watchlists. | **Implementation**: Add `async def screen_against_watchlists(document_id, lists)` that takes extracted `full_name` and `document_number` and cross-references against configurable watchlist sources (local JSON file, PostgreSQL table, or remote REST API). Return `{"screen_status": "clear|hit|review", "matched_entries": [...]}`. | **Competitor**: Comply Advantage, LexisNexis RiskView.

### I10. Document Lineage and Audit Trail with NATS Publishing
**Category**: Compliance / Observability | **Justification**: Regulatory frameworks (CBK, IFRS) require immutable audit trails for document processing. In-memory audit list is lost on restart; NATS persistent streams provide durable, queryable event lineage. | **Implementation**: Add `async def publish_audit_event(event)` that serializes `DocintAuditEvent` to NATS subject `docint.audit.{tenant_id}`. Add `async def replay_audit_stream(tenant_id, from_seq)` for historical replay. PostgreSQL materialized view for reporting. | **Competitor**: Box Shield, OpenText Content Audit.

### I11. Signature and Stamp Detection
**Category**: Document Authentication | **Justification**: Unsigned contracts and unstamped invoices have no legal weight in many jurisdictions. Computer vision detection of wet signatures and official stamps flags incomplete documents before downstream use. | **Implementation**: Add `async def detect_signatures_and_stamps(document_id)` using a locally hosted YOLO object detection model fine-tuned on document components; return `{"signatures": [{"page": 1, "bbox": ..., "confidence": 0.95}], "stamps": [...]}`. | **Competitor**: Adobe Acrobat Sign detection, Nanonets signature detection.

### I12. Incremental Re-Extraction with Field Locking
**Category**: Workflow | **Justification**: Users who correct one field (e.g. vendor name) should not have their corrections overwritten when reprocessing the rest of the document. Field locking enables surgical updates without full re-extraction. | **Implementation**: Add `async def lock_fields(document_id, field_names)` and `async def reextract_unlocked_fields(document_id, model)`. Locked fields bypass LLM re-extraction and are preserved in the final result. | **Competitor**: Hyperscience selective reprocessing, ABBYY FlexiCapture.

### I13. Bank Statement Transaction Normalization
**Category**: Financial Intelligence | **Justification**: Bank statement parsing for loan underwriting, expense categorization, and cash flow analysis requires normalizing diverse transaction narrative formats (MPESA, RTGS, bank codes) into structured debit/credit records with merchant classification. | **Implementation**: Add `async def parse_bank_statement(document_id, model)` that extracts transactions into `[{"date", "description", "debit", "credit", "balance", "category", "channel"}]`; apply regex normalization for MPESA, RTGS, and ATM transaction codes. | **Competitor**: Plaid Transactions, Finicity, Mono (Africa).

### I14. Document Quality Assessment Pre-Processing
**Category**: Pipeline Reliability | **Justification**: Submitting blurry, skewed, or partially scanned documents wastes OCR/LLM compute and produces low-quality extractions. Upfront quality gating with targeted feedback reduces wasted processing 25-35%. | **Implementation**: Add `async def assess_document_quality(document_id)` that checks image DPI, blur score (Laplacian variance), skew angle, and page coverage; returns `{"quality_score": 0-1, "issues": ["blurry", "skewed_5deg"], "processable": bool}`. Gate pipeline entry on `processable: true`. | **Competitor**: Scanbot SDK, Dynamsoft Document Scanner.

### I15. Semantic Search Across Extracted Document Content
**Category**: Retrieval / Intelligence | **Justification**: After ingesting hundreds of contracts and invoices, users need full-text semantic search ("find all contracts with liability cap below 1M USD" or "invoices from Vendor X with tax discrepancies"). Vector embeddings over extracted fields enable sub-second semantic retrieval. | **Implementation**: Add `async def embed_document(document_id, embedding_model)` that encodes extracted text via `ollama.embeddings(model="nomic-embed-text")` and stores in a PostgreSQL `pgvector` column; add `async def semantic_search(tenant_id, query, top_k, document_type_filter)` that embeds the query and retrieves nearest neighbours. | **Competitor**: AWS Kendra, Google Vertex AI Search, Cohere Embed.
