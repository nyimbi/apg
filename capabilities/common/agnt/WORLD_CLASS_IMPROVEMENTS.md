# AGNT - World Class Improvement Opportunities

### I1. Durable Persistence Layer via PostgreSQL + SQLAlchemy Async
**Category**: Infrastructure | **Justification**: In-memory dicts are lost on restart; production agent registries require durability, query capabilities, and transactional consistency. Persistent storage unlocks horizontal scaling, failover, and cross-process tenant isolation. | **Implementation**: Replace `dict` stores with `async_sessionmaker` + SQLAlchemy ORM models (`AgentDefinitionORM`, `AgentRuntimeORM`, etc.) using `asyncpg`. Add Alembic migration for initial schema. Service methods become `async` DB calls wrapped in `AsyncSession`. BoundedCache stays as L1 cache with `cache_key = (tenant_id, record_id)`. | **Competitor**: LangSmith, Flowise, and Temporal all use postgres-backed registries for agent state; Azure AI Foundry agents use CosmosDB.

### I2. Real LLM Runtime Dispatch via Ollama and OpenAI-Compatible APIs
**Category**: Execution | **Justification**: `_simulate_agent_step` is a stub that returns fake output; zero business value is produced. Wiring to a real LLM runtime is the entire point of the capability. | **Implementation**: `AgentRuntime.kind` drives dispatch — `"ollama"` → `httpx.AsyncClient.post("http://localhost:11434/api/chat")`, `"openai_compat"` → OpenAI SDK with `base_url`. Adapter pattern: `class OllamaAdapter(RuntimeAdapter)` and `class OpenAICompatAdapter(RuntimeAdapter)` keyed by `runtime.kind`. Replace `_simulate_agent_step` with `await runtime_adapter.chat(messages, model, tools)`. | **Competitor**: LangChain's `ChatOllama` / `ChatOpenAI` adapters, Haystack's `LocalChatGenerator`.

### I3. Structured Decimal-Safe Cost Accounting
**Category**: Financial | **Justification**: `float` cost arithmetic accumulates rounding error (IEEE 754). Any production billing or cost-limit enforcement built on `float` will drift. Decimal is the correct type for monetary values at any scale. | **Implementation**: Replace all `cost_usd: float` with `cost_usd: Decimal` using `from decimal import Decimal, ROUND_HALF_UP`. Model rates become `Decimal("0.030")`. Accumulation uses `sum(..., Decimal("0"))`. `to_dict()` serialises as `str(cost_usd)` to preserve precision over JSON. Add `cost_limit: Decimal | None` on `AgentRuntime`. | **Competitor**: Stripe and all serious fintech systems use Decimal; Anthropic's own usage API returns strings for this reason.

### I4. Streaming Token-Level Output via AsyncGenerator + Server-Sent Events
**Category**: UX / Execution | **Justification**: `stream_execution` currently yields synthetic `step_N` tokens with no real content. True streaming — receiving and forwarding model output token-by-token — cuts perceived latency from seconds to milliseconds and is table-stakes for modern agent UIs. | **Implementation**: Ollama `/api/chat` with `"stream": true` yields NDJSON chunks; parse with `async for line in response.aiter_lines()`. OpenAI SDK `stream=True` yields `ChatCompletionChunk`. Propagate via `AsyncGenerator[dict, None]` and expose as SSE in Flask view using `stream_with_context`. | **Competitor**: OpenAI Assistants API streaming, Anthropic streaming API, LangChain `astream`.

### I5. Vector Memory with Embedding-Based Retrieval
**Category**: Memory | **Justification**: Keyword overlap scoring in `retrieve_memory` is O(n * |query_terms|) and misses semantic similarity entirely. In any real multi-turn agent, retrieval quality directly controls output quality. | **Implementation**: On `store_memory`, call Ollama embedding endpoint (`/api/embeddings`, model `nomic-embed-text`) and store vector as `list[float]` on `MemoryRecord`. On `retrieve_memory`, embed query, compute cosine similarity with `numpy`, return top-k by score. Fall back gracefully to keyword overlap when embeddings unavailable. | **Competitor**: Chroma, Qdrant, pgvector + LangChain `VectorStoreRetriever`.

### I6. Deterministic Handoff Graph Validation with Cycle Detection
**Category**: Correctness | **Justification**: The current team policy only checks that endpoints exist. It does not detect unreachable agents, infinite loops (cycles without human-in-the-loop breaks), or disconnected subgraphs — all of which silently produce broken execution plans. | **Implementation**: Model `AgentTeam.handoffs` as a directed graph. Run DFS-based cycle detection; flag cycles that lack a `"human_review"` break node as policy violations. Compute reachability from the team's declared `entry_agent`. Expose violations in `evaluate()` rule output. Add `domain/rules.py` rule `team_handoff_graph_acyclic`. | **Competitor**: Temporal's workflow DAG validation, LangGraph's graph compilation step, Airflow DAG cycle detection.

### I7. Budget Guardrail with Hard-Stop Enforcement
**Category**: Safety / Cost | **Justification**: `AgentRuntime.cost_limit` is stored but never enforced during execution. An agent can silently exceed its budget, causing unexpected cloud bills. | **Implementation**: In `execute_pipeline` and `batch_execute`, accumulate `Decimal` cost per agent key. Before each step, check `sum(ledger) + estimated_step_cost > runtime.cost_limit`; if so, raise `BudgetExceededError(agent_id, limit, actual)`. Record a `budget_exceeded` audit event. Add `async cost_headroom(agent_id, tenant_id)` method returning remaining budget as `Decimal`. | **Competitor**: AWS Budgets hard-stop SNS actions, GCP Budget alerts + Pub/Sub cutoffs, Helicone cost limit policies.

### I8. Distributed Session State via Redis-Compatible Backend
**Category**: Scalability | **Justification**: `_session_contexts`, `_working_memory`, and `_ab_results` are process-local dicts. Multiple service replicas behind a load balancer have split-brain session state, making resume/cancel impossible across instances. | **Implementation**: Abstract `SessionStore` protocol with `get`, `set`, `delete`, `ttl`. Provide `InMemorySessionStore` (tests) and `RedisSessionStore` using `redis.asyncio`. Session keys are `{tenant_id}:{session_id}`, TTL defaults to 24 h. `AgntService.__init__` accepts `session_store: SessionStore | None = None`. | **Competitor**: LangGraph's `AsyncRedisSaver` checkpointer, Haystack's `RedisDocumentStore`.

### I9. Comprehensive OpenTelemetry Tracing
**Category**: Observability | **Justification**: `trace_sink: str` is a name only — no actual traces are emitted. Without distributed traces, debugging multi-agent pipelines is manual log archaeology. | **Implementation**: Wrap every `execute_pipeline`, `_simulate_agent_step`, `guardrail_check`, and `handoff_evaluate` call in `tracer.start_as_current_span(name, attributes={...})`. Use `opentelemetry-sdk` with `OTLPSpanExporter` targeting `trace_sink` URL. Emit `agent.id`, `tenant.id`, `model`, `tokens.used`, `cost.usd` as span attributes. Export to Jaeger or Grafana Tempo. | **Competitor**: LangSmith's built-in tracer, Weave by Weights & Biases, Arize Phoenix.

### I10. Agent Capability Negotiation and Skill Registry
**Category**: Composability | **Justification**: `orchestration_plan` scores agents by keyword overlap with tool names — a crude heuristic. A formal skill/capability registry lets the planner route tasks to the right agent based on declared functional contracts, not lexical accidents. | **Implementation**: Add `SkillDefinition` model (`skill_id`, `name`, `input_schema`, `output_schema`, `agent_ids`). `AgentDefinition` gains `skill_ids: tuple[str, ...]`. `orchestration_plan` performs schema-compatible routing: match task payload keys against `input_schema` required fields. Expose `register_skill`, `list_skills`, `assign_skill_to_agent` on `AgntService`. | **Competitor**: AutoGen's `AssistantAgent.register_function`, CrewAI skill definitions, OpenAI Assistants `tools` array.

### I11. Human-in-the-Loop Pause/Resume with Approval Inbox
**Category**: Governance | **Justification**: `resume_execution` exists but there is no mechanism to pause mid-execution and notify a human reviewer. Side-effecting runs go to `pending_review` but have no notification delivery path. | **Implementation**: Add `pause_execution(session_id, reason, reviewer_email)` that sets session status to `"paused"` and emits a `PauseApprovalRequest` event. Add `approve_paused_execution(session_id, reviewer, decision)`. Wire to APG notification capability (`notf`) for email/Slack delivery. Expose `/agnt/approvals` inbox route. | **Competitor**: Temporal's signals/queries, LangGraph's `interrupt` node, AutoGen's `HumanProxyAgent`.

### I12. Multi-Model Routing and Fallback Chain
**Category**: Resilience | **Justification**: Single-model agents fail silently when the primary model endpoint is unavailable, hitting capacity limits, or producing low-confidence outputs. Multi-model fallback turns a hard failure into a graceful degradation. | **Implementation**: `AgentDefinition` gains `fallback_models: tuple[str, ...]`. In `_simulate_agent_step`, catch `RuntimeError` / HTTP 429 / HTTP 503 and retry with the next fallback model after exponential backoff (`tenacity`). Record `model_fallback` audit event with reason and latency penalty. | **Competitor**: LiteLLM's `fallbacks`, OpenRouter routing, Azure AI's deployment fallback policy.

### I13. Fine-Grained RBAC for Agent Operations
**Category**: Security | **Justification**: All operations currently check only `tenant_id`. In practice, registering a runtime, approving a request, and running a side-effecting execution should require distinct roles (`platform_admin`, `security_reviewer`, `operator`). Without RBAC, any tenant principal can perform any operation. | **Implementation**: Add `caller_roles: set[str]` parameter to all mutating methods. Integrate with APG `auth` capability: `guard_tenant_id(tenant_id)` already exists; add `guard_role(caller_roles, required_role)`. Define role-to-operation mapping in `capability_contract.py` rule engine. Return `PermissionError` with structured reason on role mismatch. | **Competitor**: AWS IAM condition keys, GCP IAM fine-grained roles, HashiCorp Vault policies.

### I14. Execution Plan Diffing and Replay
**Category**: DevOps / Auditability | **Justification**: `plan_snapshot` is stored on `AgentExecutionRun` but never compared to future plans. Detecting plan drift — when the same team/objective now produces a different plan — is critical for compliance and regression detection. | **Implementation**: Add `diff_execution_plans(plan_id_a, plan_id_b, tenant_id)` that performs step-level diff (added/removed/changed steps, runtime assignment changes, cost limit changes). Add `replay_execution_run(run_id, tenant_id)` that re-runs planning against the stored snapshot and returns the diff. Store plan hash (`sha256(json.dumps(plan, sort_keys=True))`) on `ExecutionPlan`. | **Competitor**: Terraform plan diff, Argo CD sync diff, Temporal's workflow history replay.

### I15. Async Batch Import and Bulk Agent Registration
**Category**: Ergonomics / Throughput | **Justification**: Registering 50+ agents one-by-one via `register_agent` is O(n) round-trips with no atomicity guarantee. Bulk import with partial-failure reporting is essential for platform bootstrapping, multi-tenant onboarding, and CI/CD capability deployment pipelines. | **Implementation**: Add `async bulk_register_agents(agent_specs: list[dict], tenant_id: str, fail_fast: bool = False) -> dict` that validates all specs first, then uses `asyncio.gather` for concurrent registration with per-spec error capture. Return `{"registered": [...], "failed": [{"spec": ..., "error": ...}], "total": n}`. Validate against `validate_agent_config` before persisting any record when `fail_fast=False`. | **Competitor**: GitHub REST API bulk operations, Kubernetes batch apply, LangChain Hub bulk upload.
