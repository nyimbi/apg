# ussd_flo — World-Class Improvements

### I1. Intent-Aware Conditional DSL
**Category**: Routing Engine | **Justification**: The current string-regex condition evaluator handles only simple `key op value` pairs. Production USSD engines (e.g. Africa's Talking USSD Gateway, Telerivet) support compound boolean logic, pattern matching, and session-path predicates — the gap causes brittle multi-hop flows requiring dozens of decision nodes to model what one expression could express. | **Implementation**: Replace the `_eval_condition` regex with a small recursive-descent parser supporting `AND`, `OR`, `NOT`, `IN`, `MATCHES`, and dot-path accessors (`session.balance > 0 AND user.tier IN ['gold','platinum']`). Add `compile_condition(expr: str) -> CompiledCondition` that pre-validates at design time and caches the AST; evaluation then walks the cached tree. | **Competitor**: Africa's Talking USSD Flow Studio uses JavaScript expression sandbox; Telerivet uses Python eval with sandboxing.

### I2. Session Simulation & Dry-Run Engine
**Category**: Testing | **Justification**: Today there is no way to replay a scripted conversation against a flow without deploying it to `ussd_eng`. Teams discover broken paths in production. Every major flow platform (Twilio Studio, VXML IVR) ships an embedded simulator. | **Implementation**: Add `simulate_session(flow_id, script: list[str], language, context_seed) -> SessionTrace` that walks the flow graph node-by-node feeding the script inputs as user responses, recording each screen rendered, edge taken, and variables accumulated. Return a full trace with pass/fail assertions based on expected terminal node or variable values. | **Competitor**: Twilio Studio includes a "Test Flow" panel; VXML platforms have offline simulators.

### I3. NATS-Based Real-Time Event Streaming
**Category**: Observability | **Justification**: Audit events are stored in-process memory only — lost on restart, invisible to other services. USSD platforms need near-real-time monitoring (session abandonment spikes, A/B anomalies) feeding dashboards and alerting systems. APG's streaming platform is bytewax+NATS. | **Implementation**: Add `NatsEventPublisher` adapter that subscribes to the internal `_audit_events` list via a post-emit hook and publishes structured CloudEvents to NATS subjects `ussd.flo.events.<event_type>` using `nats-py`. The bytewax pipeline downstream can aggregate session metrics in real time. `UssdFloService.__init__` accepts an optional `event_publisher` protocol so tests inject a no-op publisher. | **Competitor**: Kafka-based USSD platforms (e.g. Mitto) publish every session event to topics; NATS achieves the same with lower operational overhead.

### I4. Automatic Dead-Path Pruning Advisor
**Category**: Flow Quality | **Justification**: Orphaned and unreachable nodes silently waste screen-space allocations and confuse operators. The current `validate_flow` only warns about them — it does not tell designers which edges to add or nodes to remove to resolve the graph cleanly. | **Implementation**: Add `compute_dead_paths(flow_id) -> DeadPathReport` that performs: (a) forward BFS from root collecting reachable set, (b) backward BFS from all `end` nodes collecting co-reachable set, (c) difference set = dead nodes. Report includes suggested edge additions to connect isolated sub-graphs and nodes that are strictly unreachable and safe to delete. | **Competitor**: Voiceflow "unreachable block" detector highlights dead sub-graphs in the canvas.

### I5. Multi-Variant A/B Testing (N-way Splits)
**Category**: Experimentation | **Justification**: The current A/B model is binary (control vs. one variant). Mature experimentation platforms (Optimizely, VWO) support N-way multi-armed bandit allocation, enabling simultaneous testing of 3-5 flow variants without running separate experiments sequentially. This cuts time-to-insight by 60% for large USSD deployments. | **Implementation**: Extend `ab_tests` model to hold `variants: list[{flow_id, weight, label}]` (weights must sum to 100). `assign_ab_flow` uses weighted modular bucketing over the session ID hash. Statistics API computes per-variant conversion rates and uses a simple chi-squared test to flag significance. | **Competitor**: Optimizely supports up to 26-way splits; Africa's Talking Flow Studio supports 3-way.

### I6. Pluggable Variable Interpolation with Template Functions
**Category**: Content Rendering | **Justification**: `render_node_translated` only supports `{var}` replacement — no formatting, no conditional display, no date/number formatting. This forces operators to pre-format values server-side and re-call the API. Real-world USSD menus need `{balance|currency:KES}` or `{name|upper}` to render reliably across languages. | **Implementation**: Add `TemplateEngine` class supporting pipes: `{expr|filter:arg}` where built-in filters include `upper`, `lower`, `currency:<code>`, `date:<fmt>`, `truncate:<n>`, `default:<fallback>`. The engine is injected into `render_node_translated` and tested independently. Operators register custom filters via `register_template_filter(name, fn)`. | **Competitor**: Jinja2 template rendering is the de facto standard; Twilio Studio uses Liquid templates.

### I7. Flow Diff and Merge
**Category**: Collaboration | **Justification**: When two designers work on a flow concurrently, the current snapshot/restore model cannot show what changed between versions — only full replace is possible. Git-style diff enables review workflows before merging changes, critical for regulated USSD services (banking, insurance). | **Implementation**: Add `diff_flow_versions(flow_id, version_id_a, version_id_b) -> FlowDiff` that computes: added/removed/modified nodes (keyed by `node_id`), added/removed/modified edges, and translation changes. `merge_flow_version(flow_id, source_version_id, strategy: 'ours'|'theirs'|'union')` applies the diff to current live graph with conflict detection. | **Competitor**: Voiceflow has "version compare" UI; Botpress tracks conversation graph diffs in git.

### I8. Accessibility & Screen-Budget Validator
**Category**: Compliance | **Justification**: USSD screens are limited to 182 characters per page on most networks (MTN/Safaricom). Content exceeding the budget is silently truncated by the network layer, producing broken UX invisible to designers. No existing OSS USSD tool validates this budget per-language per-node. | **Implementation**: Add `validate_screen_budgets(flow_id, budget: int = 182) -> ScreenBudgetReport` that iterates all nodes in all registered languages, renders each with `render_node_translated` using empty variables, measures byte length (UTF-8), and returns nodes exceeding budget with their character count and overflow amount. Warnings are integrated into `validate_flow`. | **Competitor**: Africa's Talking Flow Studio shows a live character counter; VXML platforms enforce prompt length limits at authoring time.

### I9. Flow Template Library
**Category**: Productivity | **Justification**: Operators recreate the same common USSD patterns (account balance check, PIN change, airtime top-up) from scratch every deployment. A template library reduces initial flow creation time from hours to minutes. | **Implementation**: Add `FlowTemplateLibrary` with `register_template(name, export_dict)`, `list_templates()`, `instantiate_template(name, service_code, tenant_id) -> flow_id`. Ship built-in templates: `balance_check`, `pin_change`, `airtime_topup`, `survey_3q`, `opt_in_out`. Templates are stored as plain dicts in `templates/` subdirectory and loaded at startup. | **Competitor**: Twilio Studio ships 20+ flow templates; Voiceflow has community template marketplace.

### I10. Role-Based Edit Permissions per Flow
**Category**: Security | **Justification**: The current tenant model allows any caller with `tenant_id` to modify any flow. Multi-team deployments (e.g. a bank with separate retail and corporate channels) need flow-level access control so a retail designer cannot accidentally modify a corporate flow. | **Implementation**: Add `FlowPermission` model: `{flow_id, principal_id, role: 'viewer'|'editor'|'publisher'|'owner'}`. Inject `principal_id` into mutating methods; `_check_permission(flow_id, principal_id, required_role)` raises `PermissionError` on violation. `publisher` role is the only role allowed to call `activate_flow`. Store permissions in `self.permissions: dict[str, list[FlowPermission]]`. | **Competitor**: Voiceflow has workspace-level RBAC; Botpress has fine-grained per-bot permissions.

### I11. USSD Session Replay from Logs
**Category**: Debugging | **Justification**: When a subscriber reports a broken USSD experience, operators currently have no way to replay the exact session to reproduce the failure — they must guess from sparse network logs. Session replay collapses bug reproduction from hours to seconds. | **Implementation**: Add `record_session_event(session_id, flow_id, node_id, user_input, context_snapshot)` and `replay_session(session_id) -> SessionTrace`. Session events are stored in `self.session_events: dict[str, list]`. Replay walks the stored events through `resolve_next_node` at each step and compares the expected vs. actual path, flagging divergence (e.g. due to a flow change after the session). | **Competitor**: Twilio Debugger replays webhook conversations; Voiceflow has session transcript viewer.

### I12. Composite Flow (Sub-flow Inclusion)
**Category**: Composability | **Justification**: Large USSD applications share sub-flows (login, PIN verification, confirmation dialogs) across many top-level flows. Today operators copy-paste these sub-graphs causing maintenance nightmares when a shared sub-flow changes. | **Implementation**: Add `subflow` node type that carries `subflow_id` and `return_node_id` metadata. Runtime: when `resolve_next_node` encounters a `subflow` node, it pushes the current flow context onto a call stack and switches execution to the referenced sub-flow's root. When the sub-flow hits an `end` node, the stack pops and returns to `return_node_id` in the parent. `validate_flow` checks for circular sub-flow references. | **Competitor**: Twilio Studio supports "Run Subflow" widget; IVR platforms support VXML `<subdialog>`.

### I13. Automated Translation Completeness Check
**Category**: i18n Quality | **Justification**: Missing translations cause English fallback text to appear mid-conversation in the wrong language — a jarring UX failure common in localized USSD deployments. No tool currently automates this check before flow activation. | **Implementation**: Add `check_translation_completeness(flow_id, language) -> TranslationCoverageReport` that enumerates all nodes requiring translation (title, body, item labels), cross-references the stored translation dict, and returns a per-node coverage percentage plus a list of missing keys. Integrate into `validate_flow` as a warning if any registered language is below 100% coverage. Also add `auto_fill_translations(flow_id, source_lang, target_lang, fill_strategy: 'copy_source'|'leave_empty')` for rapid bootstrapping. | **Competitor**: Phrase (i18n platform) has translation coverage dashboards; Lokalise flags missing keys.

### I14. Flow Performance Scoring
**Category**: Analytics | **Justification**: Long flows with deep nesting correlate strongly with session abandonment (Safaricom internal benchmark: each additional menu level reduces completion rate by ~8%). Designers have no in-tool feedback on flow complexity. | **Implementation**: Add `score_flow(flow_id) -> FlowScorecard` computing: average path depth from root to any end node, max path depth, cyclomatic complexity (edges - nodes + 2), menu branching factor (average outgoing edges from menu nodes), estimated session duration (assuming 10s per node), and a composite 0-100 "usability score" where penalties are applied for depth > 5, cyclomatic complexity > 20, and branching factor > 8. | **Competitor**: Voiceflow has a "Flow Complexity" metric; IVR design tools use call completion rate prediction models.

### I15. Bulk Flow Migration Across Service Codes
**Category**: Operations | **Justification**: When a telco migrant changes USSD short codes (common during MNO consolidations), operators must manually update hundreds of nodes referencing the old service code. Bulk migration with dry-run and rollback collapses a week of manual work into minutes. | **Implementation**: Add `migrate_service_code(old_code, new_code, tenant_id, dry_run: bool = True) -> MigrationReport` that scans all flows and node metadata for references to `old_code`, reports affected resources, and (when `dry_run=False`) updates them atomically with a pre-migration snapshot created automatically. Include `rollback_migration(migration_id)` that restores all affected flows to their pre-migration snapshots. | **Competitor**: Twilio has a phone number migration tool; Africa's Talking supports service code reassignment via API.
