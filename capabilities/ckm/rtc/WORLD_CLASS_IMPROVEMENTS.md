# Real-Time Collaboration (ckm_rtc) — World Class Improvements

### I1. CRDT-Native Operational Transform Engine
**Category**: Core Algorithm | **Justification**: Current conflict resolution is last-writer-wins with manual `RTCActivity.conflicts_with` tracking — this loses edits and breaks trust in co-editing. A proper CRDT engine (Yjs/Automerge semantics) guarantees convergence without coordination, eliminating the entire conflict resolution codepath. 10x better because edits are never lost and offline-then-sync Just Works. | **Implementation**: Integrate `pycrdt` (Python Yjs bindings) as the authoritative document state store. Replace `form_data_state` JSON column with a CRDT binary blob column. Service applies updates via `YDoc.apply_update()` and broadcasts the delta, not the full state. `RTCActivity.conflicts_with` becomes informational only. | **Competitor**: Notion (Yjs), Google Docs (OT), Linear (Yjs)

### I2. Multi-Pod NATS JetStream Broadcast
**Category**: Infrastructure | **Justification**: `websocket_manager._broadcast_to_page` is in-process — it cannot reach participants on other pods. Any horizontal scale attempt silently drops messages to ~50% of users. JetStream subjects per `tenant_id + page_url` give durable, exactly-once delivery across pods with consumer groups. | **Implementation**: Replace the in-process `BoundedCache` broadcast with a NATS JetStream publisher. Each pod subscribes to `apg.ckm_rtc.broadcast.{tenant_id}.>` on startup. `_broadcast_to_page` publishes to the subject; local WebSocket manager fans out to local connections only. Use `nats-py` async client. | **Competitor**: Liveblocks (Ably), Figma (internal CRDT bus), Miro (Pusher Channels)

### I3. Presence Heartbeat via Redis Sorted Sets
**Category**: Performance | **Justification**: Presence staleness detection at 90 seconds currently requires a DB query per user per page load. At 1000 concurrent users that is 1000 queries/90s = 11 QPS steady-state presence churn against PostgreSQL. Redis sorted sets give O(log N) insert and O(N) stale sweep in microseconds. | **Implementation**: `update_presence()` writes `ZADD ckm_rtc:presence:{tenant_id}:{page_url} {epoch_ms} {user_id}`. Background task runs `ZRANGEBYSCORE ... -inf {now-90s}` to find stale entries and broadcasts leave events. Remove DB writes for presence heartbeats entirely. | **Competitor**: Discord (Redis presence), Slack (Redis pub/sub)

### I4. End-to-End Encryption for Sensitive Sessions
**Category**: Security | **Justification**: Messages and form field data transit the server in plaintext. Regulated tenants (HIPAA, SOC2 Type II) require E2E encryption where the server cannot read content. Current `end_to_end_encryption` column on `RTCVideoCall` is a boolean with no key management attached. | **Implementation**: Use Signal Protocol's Double Ratchet via `python-doubleratchet`. Key exchange during session join using X3DH. Server stores only ciphertext blobs in `RTCMessage.content`. Key fingerprints stored in `RTCSession.session_variables`. Implement key rotation on participant leave. | **Competitor**: Signal (Double Ratchet), WhatsApp Business API, Wire for Business

### I5. AI-Powered Real-Time Transcription with Speaker Diarization
**Category**: AI/ML | **Justification**: `RTCRecording.auto_transcription_enabled` is stubbed with a log comment. Meeting transcription that segments by speaker, detects action items, and surfaces decisions in real-time turns recordings from archives into live productivity tools — this is the single biggest feature gap vs. Teams/Zoom. | **Implementation**: Stream audio chunks via WebRTC data channel to a local Whisper.cpp server (Ollama-compatible). Diarization via `pyannote.audio` locally hosted. Transcription segments emitted as `rtc_transcript_segment` events on the NATS subject. AI action item extraction via local Qwen2.5 model through existing Ollama integration. | **Competitor**: Microsoft Teams (Azure Cognitive), Zoom AI Companion, Otter.ai

### I6. Adaptive Bitrate Video with SFU Architecture
**Category**: Media | **Justification**: Current `RTCVideoCall` models external URLs (Teams/Zoom/Meet) but has no native media path. For tenants wanting on-premises video, there is no path at all. An SFU (Selective Forwarding Unit) eliminates the N^2 peer-to-peer bandwidth problem — a 10-person call drops from 9 upstream tracks per participant to 1. | **Implementation**: Deploy `mediasoup` (Node.js) as the SFU sidecar, controlled via `mediasoup-client` Python signaling. `webrtc_signaling.py` routes DTLS/SRTP through the SFU. Adaptive bitrate via SVC layers (VP9/AV1). `RTCVideoParticipant.connection_quality` drives layer selection. | **Competitor**: Jitsi Meet (Videobridge SFU), LiveKit, Daily.co

### I7. Optimistic Concurrency with Version Vectors for Form Co-Edit
**Category**: Consistency | **Justification**: README acknowledges "optimistic concurrency must be implemented at the service layer" but it is not. Without it, two users saving the same form field simultaneously silently discard one write. Version vectors (Lamport clocks per field) detect conflicts before commit. | **Implementation**: Add `field_versions: dict[str, int]` JSON column to `RTCPageCollaboration`. `lock_field()` increments the field's vector clock. `save_form_field()` rejects writes where submitted clock < stored clock, returning the current value for client-side merge. Use PostgreSQL `FOR UPDATE SKIP LOCKED` on the row during field save. | **Competitor**: Figma (optimistic co-edit), Airtable (field versioning)

### I8. Structured Decision Audit Trail with Cryptographic Chaining
**Category**: Governance | **Justification**: `RTCDecision` captures decisions but `decision_requires_trace` rule enforcement is a stub returning True. For regulated environments, decisions need a tamper-evident chain: each decision hash includes the hash of the prior decision in that session. Any post-hoc modification is detectable. | **Implementation**: Add `decision_hash: str` and `prior_hash: str` columns to `RTCDecision`. `capture_decision()` computes `SHA-256(decision_id + timestamp + selected_option + prior_hash)` using Python's `hashlib`. Store the chain root in `RTCSession.session_variables['decision_chain_root']`. Audit verification endpoint walks the chain. | **Competitor**: DocuSign (audit trail), Ironclad (contract chain), Workiva

### I9. Bandwidth-Aware Screen Share Quality Throttling
**Category**: Media Optimization | **Justification**: `RTCScreenShare.bandwidth_usage_kbps` is persisted but never acted upon. On congested networks, screen shares cause call audio to degrade. Automatic quality reduction when bandwidth exceeds threshold prevents calls from falling apart silently. | **Implementation**: Screen share encoder (in `webrtc_data_channels.py`) monitors RTT via RTCP feedback. When `bandwidth_usage_kbps > threshold` for 3 consecutive seconds, renegotiate the offer with reduced max bitrate constraint (`RTCRtpSendParameters.encodings[0].maxBitrate`). Emit `rtc_screenshare_quality_adjusted` event. Restore when network recovers. | **Competitor**: Zoom (network adaptation), Teams (bandwidth probing)

### I10. Waiting Room with AI-Gated Admission
**Category**: Access Control | **Justification**: `RTCVideoParticipant.in_waiting_room` exists in the schema but join/admit logic in `join_video_call()` ignores it — every participant bypasses the waiting room. A waiting room with AI identity verification (face match against enrolled photo, or meeting PIN + TOTP) prevents uninvited joins in regulated sessions. | **Implementation**: `join_video_call()` sets `in_waiting_room=True` for non-host participants when `RTCVideoCall.require_approval=True`. Host receives `rtc_participant_waiting` event. Optional AI face verification step calls local face recognition model via Ollama multimodal endpoint. Host's `admit_participant()` method flips `in_waiting_room=False` and broadcasts join event. | **Competitor**: Zoom (Waiting Room), Teams (Lobby), Google Meet (Host approval)

### I11. Breakout Room Orchestration with Auto-Assignment
**Category**: Collaboration Structure | **Justification**: `RTCVideoCall.breakout_rooms_enabled` is a boolean flag with no implementation behind it. Breakout rooms are the #1 Teams/Zoom feature for workshops. Without them, large group sessions cannot split into working groups and reconvene — a hard blocker for training and design sprint use cases. | **Implementation**: Add `RTCBreakoutRoom` model: `room_id, call_id, room_name, assigned_participants, duration_minutes, auto_close_at`. `create_breakout_rooms()` accepts count + assignment strategy (`random`, `manual`, `ai_balanced`). AI-balanced strategy uses Qwen2.5 to group by role/department from participant metadata. Timer broadcast via NATS 2 minutes before auto-close. | **Competitor**: Zoom (Breakout Rooms), Teams (Breakout Rooms), Whereby

### I12. Persistent Whiteboard with Vector Graphics Sync
**Category**: Collaboration Tools | **Justification**: `whiteboard_create()` returns a dict with a `whiteboard_id` but no state model, no sync protocol, no persistence. A whiteboard that loses its state on page reload is unusable. Persistent vector-synced whiteboards backed by CRDT make design reviews and retrospectives practical. | **Implementation**: New `RTCWhiteboard` model with `state_crdt: bytes` (Yjs binary), `elements: JSON` (Excalidraw-compatible schema). `whiteboard_update()` applies CRDT delta, persists, broadcasts delta via NATS. Render snapshots saved to S3-compatible storage (MinIO for on-prem). `whiteboard_export()` generates SVG via `cairosvg`. | **Competitor**: Miro, FigJam, Microsoft Whiteboard

### I13. Tenant-Scoped Rate Limiting with Token Bucket
**Category**: Resource Governance | **Justification**: No rate limiting exists on WebSocket message sends, join events, or screen share starts. A single misbehaving client or bot can broadcast thousands of events per second, saturating the NATS bus and degrading all tenants. Token bucket per `(tenant_id, user_id, event_type)` is the minimal viable protection. | **Implementation**: Redis-backed token bucket via `aioredis`. Each event type has a configured bucket: `message_post` (60/min), `presence_update` (10/sec), `screen_share_start` (5/min). `_validate_rate_limit()` called at top of each service method. Emit `rtc_rate_limit_exceeded` audit event when bucket empty. Tenant admin can view per-user rate stats in analytics. | **Competitor**: Pusher (per-app rate limits), Ably (token bucket per channel)

### I14. Composable Collaboration Templates
**Category**: Developer Experience | **Justification**: Every time a new APG capability needs a collaboration surface it re-implements session creation, presence, and messaging from scratch. A template registry (`sprint_retrospective`, `code_review`, `incident_bridge`, `close_review`) pre-configures session type, participant policy, decision workflow, and breakout structure — reducing integration from 200 lines to 3. | **Implementation**: `RTCCollaborationTemplate` model: `template_id, template_name, session_config, participant_policy_template, decision_workflow, breakout_config, notification_hooks`. `create_session_from_template()` materializes a session from the template, applying tenant-level overrides. Templates are versioned and can be forked per tenant. | **Competitor**: Notion Templates, Atlassian Teamwork Contracts, Miro Templates

### I15. Real-Time Collaboration Quality Score (CQS)
**Category**: Observability | **Justification**: `get_collaboration_analytics()` returns raw counts but no actionable quality signal. A Collaboration Quality Score (0-100) aggregates latency P95, consensus rate, assistance request resolution time, recording consent compliance rate, and decision trace completeness into a single SLA-trackable number. Tenants can set CQS thresholds as SLOs. | **Implementation**: `CollaborationQualityScore` Pydantic model aggregates: WebSocket latency P95 (from `RTCSession.latency_ms`), `RTCDecision` consensus rate, `RTCPageCollaboration` assistance resolution time, `RTCRecording` consent compliance rate. Computed async via background task, stored in Redis with 5-minute TTL. Exposed via `get_collaboration_quality_score()` service method and `/ckm-rtc/api/v1/quality-score` endpoint. | **Competitor**: Zoom Quality Dashboard, Teams Call Analytics, Datadog SLO tracking
