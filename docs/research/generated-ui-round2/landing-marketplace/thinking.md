# Landing + Marketplace Raw Reasoning

The current APG landing page is actionable but mostly a launcher. The marketplace lists generated blueprints but does not tell a buyer why a connector is a good fit, whether it is installable, or how to prove the generated app is ready.

Vercel is the best leader because the deploy button is a model for reducing time-to-first-value. The APG equivalent should not be "deploy to a cloud" because the generated apps are local/offline and self-contained. The equivalent is a live demo boot path: open the workspace, inspect marketplace blueprints, inspect OpenAPI, and run self-test.

Salesforce AppExchange and Atlassian Marketplace establish that marketplace pages need trust and proof, not just discovery. APG can do better because the generated app already knows its routes, workflows, agents, capabilities, and local assets. That makes install proof concrete instead of marketing copy.

Rejected: external demo embeds or hosted deploy buttons. They would violate the no-CDN/no-external-runtime ground rule and misrepresent the generated app. Rejected: adding marketplace package installation. That is a product decision outside this UI pass. Rejected: fake reviews/ratings. Trust should come from generated proof, not fabricated social proof.
