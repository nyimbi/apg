# Relationships

APG supports three relationship kinds: `has_many`, `belongs_to`, and `has_one`. Through-associations are declared with `through`.

## belongs_to

`belongs_to` adds a foreign-key field (`<parent>_id`) to the current table and registers the association:

```apg
table Order {
    order_number: str;
    belongs_to:   Customer;   // adds customer_id: str field
    order_date:   date;
    total:        decimal = 0.0;
}
```

Generated column: `customer_id TEXT NOT NULL`.

## has_many

`has_many` is the inverse of `belongs_to`. It generates nested REST endpoints:

```apg
table Customer {
    name:     str;
    email:    str;
    has_many: Order;
}
```

Generated endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/entities/Customer/<id>/orders` | List all orders for customer |
| `POST` | `/entities/Customer/<id>/orders` | Create order for customer |

## has_one

`has_one` is a `has_many` with a uniqueness constraint — at most one child record exists:

```apg
table User {
    username:  str;
    email:     str;
    has_one:   Profile;
}

table Profile {
    belongs_to: User;
    bio:        str?;
    avatar_url: str?;
}
```

Generated endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/entities/User/<id>/profile` | Fetch the user's profile |
| `PUT` | `/entities/User/<id>/profile` | Create or replace profile |

## through (many-to-many)

`through` declares a many-to-many relationship via a join table:

```apg
table Student {
    name:     str;
    has_many: Course through Enrollment;
}

table Course {
    title:    str;
    has_many: Student through Enrollment;
}

table Enrollment {
    belongs_to: Student;
    belongs_to: Course;
    enrolled_at: date;
    grade:       str?;
}
```

Generated endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/entities/Student/<id>/courses` | List courses for student |
| `POST` | `/entities/Student/<id>/courses` | Enroll student in a course |
| `DELETE` | `/entities/Student/<id>/courses/<course_id>` | Drop a course |

## Full multi-level example

```apg
module shop version 1.0.0 {}

table Customer {
    name:     str;
    email:    str;
    has_many: Order;
}

table Order {
    belongs_to:   Customer;
    order_number: str;
    order_date:   date;
    status:       str = "draft";
    has_many:     OrderLine;
}

table OrderLine {
    belongs_to:   Order;
    product_code: str;
    quantity:     int = 1;
    unit_price:   decimal;
}

app Shop { routes: ["/customers", "/orders", "/order-lines"]; }
```

Nested endpoint tree:

```
GET  /entities/Customer/records
POST /entities/Customer/records
GET  /entities/Customer/<id>/orders         ← has_many
POST /entities/Customer/<id>/orders
GET  /entities/Order/<id>/lines             ← has_many
POST /entities/Order/<id>/lines
```

## Foreign-key conventions

- `belongs_to: Foo` adds `foo_id: str` automatically.
- Manual foreign keys (e.g. `customer_id: str`) still work without a `belongs_to` declaration — the nested endpoints just won't be generated.
- IDs are UUID v7 strings generated by the app; the schema constraint is `TEXT NOT NULL`.
